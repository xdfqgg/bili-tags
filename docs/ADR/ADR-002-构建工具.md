# ADR-002：构建工具 —— esbuild

- 状态：✅ Accepted
- 日期：2026-08-23

## 背景

选用 TypeScript（ADR-001）后需要编译打包。扩展有三个独立入口（content script / background / options），需要「编译 TS → 产出浏览器可直接加载的 dist 目录」。

## 决策

**esbuild**：毫秒级编译打包，配置约 10 行。

## 备选方案

| 方案 | 取舍 |
|------|------|
| 无构建（手工 tsc） | 无依赖但需手工处理多入口，MV3 的 ES module 加载手工维护成本高 |
| Vite | 完整开发框架，但核心卖点（dev server、HMR 热更新、资源处理）是给网站的 —— 扩展开发要手动重载，HMR 无价值；为用不上的功能付配置成本 |

## 结果与影响

- 构建快、配置轻，符合扩展场景
- 无 HMR —— 对扩展无损失（扩展本来就要在 chrome://extensions 手动刷新）
